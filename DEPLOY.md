# Публикация редактора схем на Cloudflare Pages

Готовый сайт лежит в папке **`publish/`**:

```
publish/
  index.html        — разметка
  styles.css        — стили
  app.js            — вся логика (~73 КБ)
  functions/
    api/
      report.js     — приём отчётов о проблемах  (POST /api/report)
      reports.js    — выгрузка отчётов для ревью   (GET  /api/reports?key=…)
```

Cloudflare Pages — бесплатный хостинг. Лимит 25 МБ **на файл**, у нас килобайты — проблем не будет.

> ⚠️ ВАЖНО про бэкенд (сбор отчётов): папка `functions/` работает **только** при деплое
> через **Wrangler** или **Git**. Через drag-and-drop в дашборде функции НЕ подхватываются —
> загрузится только статика, а кнопка «Сообщить о проблеме» будет откатываться на ручное
> копирование. Для рабочего сбора отчётов используй Способ A или B ниже.

---

## Шаг 1. Создать хранилище KV (один раз)

Нужен Node.js. Из папки проекта:

```bash
npx wrangler login                                  # вход в Cloudflare (откроется браузер)
npx wrangler kv namespace create REPORTS            # создать хранилище отчётов
```

Команда выведет `id` нового namespace — запомни его (понадобится при привязке).

---

## Шаг 2. Деплой

### Способ A — Wrangler (рекомендую)

```bash
# из папки проекта; деплоится содержимое publish вместе с functions/
npx wrangler pages deploy publish --project-name=metro-editor
```

Первый запуск создаст проект, дальнейшие — выложат новую версию.
Адрес будет вида `https://metro-editor.pages.dev`.

### Способ B — Git (автодеплой при коммите)

1. Залей проект в репозиторий GitHub.
2. Cloudflare → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
3. Настройки сборки:
   - **Build command** — пусто
   - **Build output directory** — `publish`
4. **Save and Deploy**. Дальше каждый `git push` обновляет сайт.

---

## Шаг 3. Привязать KV и задать секрет (в дашборде, один раз)

Cloudflare → твой Pages-проект → **Settings**:

1. **Functions → KV namespace bindings → Add binding**
   - Variable name: `REPORTS`
   - KV namespace: выбрать созданный на шаге 1
2. **Environment variables → Add variable**
   - Name: `ADMIN_KEY`
   - Value: придумай длинный секрет (он защищает выгрузку отчётов), например `r7K2-…`
   - Тип: можно **Secret** (зашифрованный)
3. Сделай **Retry deployment** (или новый деплой), чтобы привязки применились.

После этого кнопка «🐞 Сообщить о проблеме» в редакторе будет складывать отчёты в KV.

## Как смотреть отчёты

### Удобный просмотрщик (рекомендую)

Открой на боевом домене:

```
https://<твой-домен>.pages.dev/reports.html
```

Введи `ADMIN_KEY` в поле вверху — он сохранится в браузере, в код не зашит. Страница покажет
все отчёты карточками: предпросмотр самой схемы (рендерится из кода карты), описание проблемы,
число линий/узлов, зум, угол, браузер, страну и сворачиваемый журнал событий. Кнопка
«Открыть в редакторе» открывает карту из отчёта прямо в редакторе (через `#map=…`), а
«Скачать JSON карты» сохраняет код карты файлом.

Файл лежит в `publish/reports.html` — деплоится вместе с остальной статикой. Локальным
двойным кликом он работать не будет: ему нужен тот же домен, что и у `/api/reports`.

### Сырой JSON (как было)

```
https://<твой-домен>.pages.dev/api/reports?key=ВАШ_ADMIN_KEY
```

Вернётся JSON со всеми отчётами (новые сверху): описание, код карты, журнал, браузер, дата.

### Автоматическая проверка

Настроена ежедневная проверка в 9:00 (через Cowork/Claude): каждое утро дёргает `/api/reports`,
отбирает отчёты за прошедшие сутки и присылает сводку — но только если есть новые.

Через CLI можно посмотреть и напрямую в KV:

```bash
npx wrangler kv key list --binding=REPORTS
npx wrangler kv key get "report:<id>" --binding=REPORTS
```

---

## Поделиться готовой картой

Кнопка «🔗 Поделиться ссылкой» кодирует всю схему прямо в адрес (`…/#map=…`) и копирует ссылку.
Открыл такую ссылку — карта сразу загрузилась. Бэкенд для этого не нужен, работает и на статике.

---

## Локальная проверка

Открой `publish/index.html` двойным кликом — редактор работает как одиночный `metro-editor.html`.
Кнопка отчёта при локальном открытии не достучится до `/api/report` и предложит скопировать текст
вручную — это нормально, на боевом домене она будет отправлять на бэкенд.
